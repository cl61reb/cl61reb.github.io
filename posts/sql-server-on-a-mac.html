SQL Server on a Mac: Setup Guide

4 November 2026

You can run a full Microsoft SQL Server on your Mac for free in about 20 minutes, using Docker and VS Code.

What you'll end up with: SQL Server Developer edition (free, full featured) running in the background, and VS Code to write and run your SQL scripts.

Works on: Apple Silicon Macs (M1, M2, M3, M4, M5) and older Intel Macs. To check yours, click the Apple menu > About This Mac and look at "Chip" or "Processor".

You'll need: an internet connection, your Mac login password, and about 10GB of free disk space.

Step 1: Install Rosetta (Apple Silicon only)

SQL Server is only built for Intel chips, so Apple Silicon Macs need Rosetta to translate it. Intel Mac users can skip this step.

  1. Open Terminal (press Cmd + Space, type Terminal, press Enter)

  2. Copy and paste this, then press Enter:

softwareupdate --install-rosetta --agree-to-license

  1. You should see Install of Rosetta 2 finished successfully. If you also see a "Package Authoring Error" line, ignore it; it's a harmless Apple warning.

Step 2: Install Docker Desktop

Docker runs SQL Server in a sealed box (a "container") on your Mac. It's free for personal and education use.

  1. Go to docker.com/products/docker-desktop and click Download Docker Desktop

  2. Choose Mac with Apple Silicon (or Mac with Intel chip if that's what you have)

  3. Open the downloaded .dmg file and drag Docker into Applications

  4. Open Docker from Applications. Accept the terms; you can skip signing in and the survey

  5. Wait until the whale icon in the menu bar stops moving and Docker says Engine running

  6. Check two settings (click the gear icon). They're usually already right:

    • General: "Use Rosetta for x86_64/amd64 emulation on Apple Silicon" is ticked

    • Resources: Memory is 4GB or more

  7. If you changed anything, click Apply & Restart

  8. Open a new Terminal window and check it works:

docker --version

You should see something like Docker version 28.x.x. If you get "command not found", see Troubleshooting below.

Step 3: Install VS Code and the SQL Server extension

VS Code is a free editor from Microsoft where you'll write and run your SQL. (Azure Data Studio has been retired, so use this instead.)

  1. Download VS Code from code.visualstudio.com, then drag it into Applications and open it

  2. Click the Extensions icon in the left sidebar (four small squares)

  3. Search for SQL Server (mssql), choose the one published by Microsoft, and click Install

  4. A new SQL Server icon appears in the left sidebar

If VS Code asks you to sign in to GitHub, you can skip it. It's only for extra features you don't need here.

Step 4: Create your SQL Server

Make sure Docker Desktop is open and running first.

  1. In VS Code, click the SQL Server icon in the left sidebar

  2. In the Connections panel, open the menu (the ... or + button) and choose Create Local SQL Container

  3. Click Get Started and follow the prompts:

    • Version: pick the newest SQL Server (2025)

    • Password: at least 8 characters, with upper case, lower case, a number and a symbol (for example Uni!Sql2026). Write it down

    • Name: anything you like, such as sqlserver

    • Tick to accept the licence

  4. Click Create. The first time, it downloads about 1.5GB, so allow 5 to 10 minutes

  5. When it finishes, VS Code connects to your new server automatically

Prefer Terminal?

This does the same thing (change the password to your own):

docker run -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='Uni!Sql2026' \
  -p 1433:1433 --name sqlserver --platform linux/amd64 \
  -d mcr.microsoft.com/mssql/server:2025-latest

Then in VS Code add a connection with server localhost,1433, authentication SQL Login, user sa and your password. Tick Trust server certificate if asked.

Step 5: Test it and create your first database

  1. In the SQL Server panel, right click your connection and choose New Query

  2. Paste this and click Execute (the play button at the top right), or press Cmd + Shift + E:

SELECT @@VERSION;

  1. If you see a line starting Microsoft SQL Server 2025, it's working

  2. Now create a database and a test table:

CREATE DATABASE TestDB;
GO

USE TestDB;
GO

CREATE TABLE Customer (
    CustomerID INT IDENTITY(1,1) PRIMARY KEY,
    FullName   NVARCHAR(100) NOT NULL,
    Email      NVARCHAR(255) UNIQUE
);

INSERT INTO Customer (FullName, Email)
VALUES ('Alex Smith', 'alex@example.com'),
       ('Sam Jones',  'sam@example.com');

SELECT * FROM Customer;

  1. You should see two rows. Refresh the connection in the sidebar and TestDB appears under Databases

Day to day use

  • Starting up next time: open Docker Desktop first, then VS Code. If the server is stopped, VS Code offers to start it when you connect

  • Stopping it: close Docker Desktop, or stop the container from the Containers tab in Docker. Your databases are kept

  • Keep your scripts as files: save your work as .sql files (for example 01_create_database.sql, 02_create_tables.sql, 03_populate_tables.sql, 04_queries.sql). If you ever delete the container, its databases go with it, but you can rebuild everything in seconds by running the files in order

  • Re-runnable scripts: start your create script with DROP DATABASE IF EXISTS YourDB; so you can run it again from scratch

Troubleshooting

ProblemFix
zsh: command not found: dockerMake sure Docker Desktop is open and says Engine running, then open a new Terminal window. Still failing? Docker Settings > Advanced > choose System, then Apply & Restart
Container starts then stops straight awayUsually a weak password or too little memory. Use a stronger password and give Docker 4GB or more in Settings > Resources
VS Code can't connectCheck the container is running in Docker's Containers tab. Use localhost,1433, user sa, and tick Trust server certificate
"Port 1433 is already allocated"Another SQL Server is already running. Stop it in Docker, or use -p 1434:1433 and connect to localhost,1434
DROP DATABASE says the database is in useRun USE master; first, then drop it
Rosetta "Package Authoring Error"Harmless; ignore it if the last line says it finished successfully
